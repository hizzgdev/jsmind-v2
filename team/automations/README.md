# team/automations/

这个目录放自动化流程与团队协作约定，按流程分目录：一条流程一个子目录，该流程自己的文档、脚本和配置都收在里面。

## 目录自包含

每个流程目录都是自包含的，自己的 README、脚本、SOUL、重建清单都放在自己目录里，入口就是该目录的 README。要了解、部署或重建某条流程，只读那一个目录就够，不需要先读别处的说明。

## 子目录

| 目录 | 定位 |
| --- | --- |
| `hubie/` | 基于例程监听与内部消息的团队协作流程：组织分工、工作流程、沟通约定与重建清单。 |
| `weka/` | 基于 GitHub webhook + Kanban 的开发流程：webhook 脚本、SOUL、部署步骤与重建清单。 |
| `bots/` | 早期 bot 文档。其中 `bots/legacy/` 已废弃，只作历史参考，不要照它开工。 |
| `skills/` | 供 agent 使用的 skill，例如 `skills/jsmind-review/`（PR 审查方法）。 |

## 目录约定

- 每个流程目录的文档只描述自己。不引用另一个流程目录，不比较两套流程，也不提对方的标签或成员。
- 判断某个 Issue / PR 走哪条流程，看它当前带的标签，然后进入对应目录的 README。不需要读另一套文档，也不需要拿两套文档互相印证。
- 不设目录级负责人。每条流程由当前执行它的人维护，改动统一走 PR。
- 新增流程时按同样方式开一个子目录，把该流程的全部材料放进去，再回到本文件补一行定位。
