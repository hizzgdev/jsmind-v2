# jsMind 2.2.0

Minor release on the 2.x preview line (npm tag `v2-preview`). The minor carries breaking changes, so read the list below before upgrading.

## Install

```bash
npm i jsmind@2
```

`npm i jsmind` still installs v1 (0.9.x).

## What changed

### Breaking

- `context --focus` is removed. `--highlight` replaces it: `jsmind context map.json --focus "Earth"` now exits 2 as a usage error instead of searching, so any script or prompt still passing `--focus <text>` has to switch to `--highlight <text>` — repeatable, and searched across the whole document rather than the levels `--depth` shows.

### Features

- feat(cli): make the write flags per-command and report create's root id (#186)
  - `--dry-run`, `--output` and `--backup` exist only on the commands that write from now on. `jsmind validate x.json --output y.json` used to exit 0 with the flag read by nobody and no warning; it now names the flag on stderr, and `--strict` refuses it with exit 2. `create --json` prints `{"file": ..., "rootNodeId": ...}`, so the command after it no longer has to go looking for the root's id.
- feat(cli): make a bare jsmind print the index and --help the full manual (#175)
  - `jsmind` on its own prints an index instead of the whole reference; `jsmind --help` and `jsmind help` print the complete reference, which now carries the `export` block and the `mind set-style` field table.
- feat(cli): locate nodes by text in context, and give every node its parentId (#173)
  - `context --focus` is gone, replaced by `--highlight`: the whole label compared case-insensitively, repeatable, searched across the entire document rather than the levels `--depth` shows, printing an id path instead of a candidate list (`(no match)` when nothing matches). `context --json` gives every node a `parentId` (`null` on the root) and puts a `highlighted` block first when `--highlight` is used.

### Fixes

- fix(cli): say what a tone is and that each colour flag paints one part (#177)
